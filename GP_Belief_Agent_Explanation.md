# Агент алгоритма HPO с использованием GP Belief State

Этот документ кратко описывает архитектуру и логику работы агента обучения с подкреплением (RL), использующего Гауссовские процессы (GP) для формирования *Belief State* (состояния убеждения) в рамках задачи оптимизации гиперпараметров (HPO).

## 1. Концепция: Зачем нужен Belief State?
Поиск оптимальных гиперпараметров — это процесс частичной наблюдаемости (POMDP). Агент, находясь в конкретной точке пространства, видит только текущее значение метрики и свои локальные шаги, но не знает глобального ландшафта целевой функции.

Чтобы решить эту проблему, используется **Гауссовский процесс (Gaussian Process, GP)** в качестве внутренней суррогатной модели среды. GP выполняет роль долгосрочной памяти агента:
1. Он собирает историю поиска (пройденные точки $X$ и полученные метрики/награды $y$).
2. На каждом шаге агент "опрашивает" GP о текущем местоположении.
3. Ответ GP формирует *Belief State* — математическое "убеждение" агента о том, как выглядит ландшафт функции вокруг него.

## 2. Расширенное пространство наблюдений (Observation Space)
Классический RL-агент для HPO видит только текущие нормализованные гиперпараметры, разницу метрик и шаг. В новой среде (`GPBeliefContinuousPipelineEnv`) к вектору наблюдений динамически конкатенируются **дополнительные признаки от GP**:

* **$\mu(x)$ (Predictive Mean):** Ожидаемое значение функции в текущей точке.
* **$\sigma(x)$ (Predictive Standard Deviation):** Уровень неопределенности в текущей точке. Служит естественным сигналом для Exploration (исследования) — чем выше $\sigma$, тем меньше агент знает об этой области.
* **$\nabla \mu(x)$ (Градиент среднего):** Вектор направления локального роста функции (вычисляется методом конечных разностей). Указывает агенту сторону Exploitation (эксплуатации).
* **$\nabla \sigma(x)$ (Градиент неопределенности):** Вектор, указывающий, в каком направлении быстрее всего возрастает неизвестность. Указывает агенту сторону Exploration (исследования).

Благодаря этим признакам, алгоритм (например, SAC или PPO) может выучить мета-эвристику, балансирующую между исследованием неизученных зон ($\nabla \sigma$) и спуском/подъёмом по градиенту ($\nabla \mu$).

## 3. Настройка Гауссовского процесса (Особенности конфигурации)
При интеграции с детерминированными бенчмарками (Schwefel, Rosenbrock, Rastrigin) возникают краевые случаи при аппроксимации. Чтобы оптимизатор `scikit-learn` не уходил в бесконечные циклы переобучения на малых выборках, предприняты следующие меры:

* **Фиксация уровня шума (`WhiteKernel(noise_level=1e-4, bounds="fixed")`):** 
Тестовые функции не имеют стохастического шума (в отличие от реальных задач ML). Без фиксации оптимизатор пытается свести дисперсию ядра в идеальный `0.0`, что вызывает `ConvergenceWarning` и `LinAlgError` (сингулярная ковариационная матрица). Малый фиксированный шум (jitter) гарантирует математическую стабильность.
* **Ограничение масштаба (`length_scale_bounds=(1e-2, 1e2)`):**
Так как входное пространство $X$ аппаратно нормализовано в диапазон `[0, 1]`, сверхмалые (коллапс) или гигантские значения длины масштаба лишены физического смысла и просто свидетельствуют о нехватке точек на первых шагах эпизода.
* **Ядро (Matern $\nu=2.5$):**
Обеспечивает дважды дифференцируемое сглаживание, идеально подходящее для моделирования гладких и полугладких непрерывных функций HPO.

## 4. Алгоритм взаимодействия
1. Поднимается среда, инициализируется пустой буфер истории для эпизода.
2. Агент делает шаг (step).
3. Среда вычисляет новую награду и обновляет `GaussianProcessRegressor` по собранным $X$ и $y$ (обучение `.fit()`). Обновление можно регулировать параметром `gp_update_freq`.
4. Среда запрашивает у обновленного GP $\mu$, $\sigma$ и градиенты для новой точки.
5. Эти свойства отдаются в модуль Actor-Critic (используя алгоритм **SAC** Tianshou v2.0.0). Акторы учатся предсказывать непрерывные смещения, используя готовое представление о ландшафте, вместо того чтобы строить его внутри RNN с нуля.
