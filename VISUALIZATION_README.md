# Визуализация 2D оптимизации

Этот скрипт позволяет визуализировать траекторию поиска агента на 2D оптимизационных задачах.

## Использование

### Базовая команда (Rastrigin):
```bash
python run_experiment_2d_visualize.py --config configs/function_2d_test.yaml
```

### Тестирование на разных функциях:

**Sphere (простая выпуклая функция):**
```bash
python run_experiment_2d_visualize.py --config configs/function_2d_sphere.yaml
```

**Rosenbrock (долина - сложная для оптимизации):**
```bash
python run_experiment_2d_visualize.py --config configs/function_2d_rosenbrock.yaml
```

**Ackley (много локальных минимумов):**
```bash
python run_experiment_2d_visualize.py --config configs/function_2d_ackley.yaml
```

## Параметры конфигурации

### Увеличенные параметры для лучшего поиска и transfer learning:

- **num_bins: 300** - значительно увеличено для более точного поиска и лучшего переноса знаний
- **max_steps: 1000** - больше шагов для исследования пространства в одном эпизоде
- **step_sizes: [50, 40, 30, 25, 20, 15, 12, 10, 8, 6, 5, 4, 3, 2, 1]** - много маленьких шагов для точной настройки и больших для выхода из локальных минимумов
- **total_timesteps: 200000** - больше времени обучения для освоения большего пространства действий

### Настройка шагов

Разнообразие размеров шагов позволяет агенту:
- Делать очень большие шаги (50, 40, 30) для быстрого исследования и выхода из локальных минимумов
- Делать большие шаги (25, 20, 15) для широкого исследования пространства
- Делать средние шаги (12, 10, 8, 6, 5) для баланса между исследованием и эксплуатацией
- Делать маленькие шаги (4, 3, 2, 1) для точной настройки вблизи оптимума

Большое количество маленьких шагов особенно важно для transfer learning, так как позволяет агенту адаптироваться к новым функциям с высокой точностью.

## Результаты

Графики сохраняются в `logs/<agent_name>/trajectory_2d.png` и включают:
- Контурную карту функции с траекторией поиска
- 3D визуализацию поверхности с траекторией

## Transfer Learning (Перенос знаний)

Скрипт поддерживает тестирование предобученной модели на другой функции для проверки переносимости знаний.

### Примеры использования:

**1. Обучение модели на Rastrigin:**
```bash
python run_experiment_2d_visualize.py --config configs/function_2d_test.yaml
```
Модель будет сохранена в `logs/PPO/model_2d.zip`

**2. Тестирование обученной модели на Sphere (zero-shot transfer):**
```bash
python run_experiment_2d_visualize.py \
    --config configs/function_2d_sphere.yaml \
    --pretrained-model logs/PPO/model_2d.zip \
    --transfer-learning
```

**3. Дообучение модели на новой функции (с повышенным exploration):**
```bash
python run_experiment_2d_visualize.py \
    --config configs/function_2d_rosenbrock.yaml \
    --pretrained-model logs/PPO/model_2d.zip \
    --transfer-learning \
    --fine-tune-steps 20000 \
    --exploration-boost 2.5
```

**4. Для предотвращения переобучения рекомендуется:**
- Использовать `--fine-tune-steps` не менее 10000-20000 шагов
- Увеличить `--exploration-boost` до 2.0-3.0 для лучшей адаптации
- Это поможет агенту не застревать в локальных минимумах и лучше исследовать новое пространство

### Сценарии переноса знаний:

- **Sphere → Rastrigin**: Простая → Сложная (много локальных минимумов)
- **Rastrigin → Sphere**: Сложная → Простая (проверка переобучения)
- **Rastrigin → Rosenbrock**: Много минимумов → Долина (разные ландшафты)
- **Rosenbrock → Ackley**: Долина → Крутые склоны (разные типы сложности)

### Параметры:

- `--pretrained-model`: Путь к файлу предобученной модели (.zip)
- `--transfer-learning`: Включить режим переноса знаний
- `--fine-tune-steps`: Количество шагов для дообучения (0 = zero-shot)
- `--exploration-boost`: Множитель для увеличения exploration (по умолчанию 1.5, рекомендуется 2.0-3.0 для лучшей адаптации)

### ⚠️ Важно для Transfer Learning:

Для успешного переноса знаний **параметры окружения должны совпадать**:
- `num_bins` - должно быть одинаковым
- `step_sizes` - должно быть одинаковым
- `dimensions` - должно быть одинаковым (всегда 2D для визуализации)

Можно менять только:
- `function_name` - функция оптимизации
- `bounds` - границы поиска (но лучше использовать одинаковые для сравнения)
- `max_steps` - количество шагов в эпизоде

Если параметры окружения не совпадают, модель может не загрузиться или работать некорректно.

### 🔧 Решение проблемы переобучения при Transfer Learning:

Если агент быстро сходится к длинным шагам и застревает около нуля (но не находит минимум), это признак переобучения. Решения:

1. **Увеличить exploration boost:**
   ```bash
   --exploration-boost 2.5  # или даже 3.0
   ```

2. **Использовать больше шагов fine-tuning:**
   ```bash
   --fine-tune-steps 20000  # или больше
   ```

3. **Комбинированный подход:**
   ```bash
   python run_experiment_2d_visualize.py \
       --config configs/function_2d_sphere.yaml \
       --pretrained-model logs/PPO/model_2d.zip \
       --transfer-learning \
       --fine-tune-steps 30000 \
       --exploration-boost 2.5
   ```

Это заставит агента больше исследовать новое пространство вместо быстрого перехода к эксплуатации старых паттернов.

### Сравнение результатов:

Для оценки эффективности transfer learning рекомендуется:

1. **Обучение с нуля** на целевой функции:
   ```bash
   python run_experiment_2d_visualize.py --config configs/function_2d_sphere.yaml
   ```

2. **Transfer learning** с предобученной модели:
   ```bash
   python run_experiment_2d_visualize.py \
       --config configs/function_2d_sphere.yaml \
       --pretrained-model logs/PPO/model_2d.zip \
       --transfer-learning
   ```

3. **Сравнить**:
   - Скорость сходимости (если используется fine-tuning)
   - Финальное качество решения
   - Траекторию поиска (визуально)

Графики сохраняются с разными именами:
- `trajectory_2d.png` - обучение с нуля
- `trajectory_2d_transfer.png` - zero-shot transfer
- `trajectory_2d_transfer_finetune{N}.png` - с дообучением

## Сравнение функций

- **Sphere**: Простая выпуклая функция - должна быть легкой для оптимизации
- **Rastrigin**: Много локальных минимумов - проверяет способность выходить из локальных минимумов
- **Rosenbrock**: Долина - проверяет способность следовать по долине к оптимуму
- **Ackley**: Много локальных минимумов + крутые склоны - очень сложная задача
