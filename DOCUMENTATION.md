# Документация проекта HPO_RL

## Обзор

HPO_RL — это фреймворк на основе обучения с подкреплением (Reinforcement Learning, RL) для оптимизации гиперпараметров (Hyperparameter Optimization, HPO), в настоящее время тестируемый на задачах оптимизации функций. Проект направлен на использование RL-агентов для изучения оптимальных стратегий выбора гиперпараметров с фокусом на перенос знаний между различными задачами оптимизации.

## Статус проекта

**Статус**: В разработке (INDEV)

Проект находится в активной разработке, основная архитектура создана, но несколько компонентов требуют доработки и стандартизации.

## Архитектура

### Основные компоненты

Проект следует модульной архитектуре со следующими основными компонентами:

1. **Backends** (`hpo_rl/backends/`): Движки оценки, вычисляющие награды
2. **Environments** (`hpo_rl/environments/`): RL-среды, определяющие пространства состояний/действий
3. **Models** (`hpo_rl/models/`): ML-модели (в настоящее время минимальное использование)
4. **Trainers** (`hpo_rl/trainers/`): Логика обучения моделей
5. **Core** (`hpo_rl/core/`): Паттерн фабрики, строители и система регистрации

### Детали компонентов

#### 1. Backends (`EvaluationBackend`)

Backends отвечают за оценку конфигураций гиперпараметров и возврат значений награды.

**Доступные Backends:**

- **`OptimizationBenchmarkBackend`**: Оценивает эталонные функции оптимизации (sphere, rastrigin, rosenbrock, ackley, griewank, schwefel, levy, michalewicz)
  - Поддерживает настраиваемые размерности, шум и максимизацию/минимизацию
  - Используется для тестирования оптимизации функций
  - Расположен в `hpo_rl/backends/function.py`

- **`DummyBackend`**: Простой тестовый backend, награждающий близость к предопределенному оптимуму
  - Полезен для отладки и тестирования
  - Расположен в `hpo_rl/backends/dummy.py`

- **`RealTrainingBackend`**: Полноценный backend обучения для реальных ML-моделей
  - Создает модели, обучает их и вычисляет награды на основе потерь валидации
  - Поддерживает несколько моделей и стратегий награды
  - Расположен в `hpo_rl/backends/real.py`

- **`TableBackend`**: Устаревший backend, использующий предзаписанные CSV-данные (помечен как устаревший)
  - Использует KDTree для поиска ближайшего соседа
  - Расположен в `hpo_rl/backends/table.py`

**Базовый интерфейс:**
```python
class EvaluationBackend(ABC):
    @abstractmethod
    def evaluate(self, config: Dict[str, Any]) -> float:
        """Возвращает награду для данной конфигурации гиперпараметров"""
```

#### 2. Environments (`BaseHPOEnv`)

Environments определяют формулировку RL-задачи, включая пространства наблюдений, пространства действий и логику награды.

**Доступные Environments:**

- **`CyclicPipelineEnv`**: Итеративно корректирует гиперпараметры циклическим образом
  - Пространство действий: Discrete(3) - уменьшить, оставить, увеличить
  - Циклически проходит по гиперпараметрам по одному
  - Предоставляет промежуточные награды за улучшения
  - Расположен в `hpo_rl/environments/cycle_move_pipeline.py`

- **`ContinuousPipelineEnv`**: Последовательный выбор с непрерывными действиями
  - Пространство действий: Box[0, 1] - нормализованное значение для каждого гиперпараметра
  - Выбирает все гиперпараметры последовательно за один эпизод
  - Награда только при завершении эпизода
  - Расположен в `hpo_rl/environments/continuous_pipeline_env.py`

- **`DiscretizedPipelineEnv`**: Последовательный выбор с дискретизированными непрерывными действиями
  - Пространство действий: Discrete(num_bins) - дискретизированные непрерывные значения
  - Похож на ContinuousPipelineEnv, но с дискретными действиями
  - Расположен в `hpo_rl/environments/discretized_pipeline_env.py`

- **`DiscretePipelineEnv`** (MaskablePPO): Дискретное пространство действий с поддержкой маскирования
  - Расположен в `hpo_rl/environments/masked_pipeline_env.py`

- **`StrategyEnv`**: Среда на основе стратегии
  - Расположен в `hpo_rl/environments/lab_env.py`

**Базовый интерфейс:**
```python
class BaseHPOEnv(gym.Env):
    def __init__(self, hp_space: Dict[str, Any], backend: EvaluationBackend)
    def reset(self, seed, options) -> (observation, info)
    def step(self, action) -> (observation, reward, terminated, truncated, info)
```

**Пространства наблюдений:**
- Обычно включают: текущий шаг, выбранные значения (нормализованные), индикатор активного параметра
- Формат: `Dict[str, np.ndarray]` (совместимо с Gymnasium MultiInputPolicy)

**Пространства действий:**
- Различаются по средам: Discrete или Box
- Действия преобразуются в значения гиперпараметров через нормализацию и масштабирование

#### 3. Система Core Factory

Проект использует паттерн фабрики с регистрацией для расширяемости:

**Система регистрации** (`hpo_rl/core/register.py`):
- `initialize_framework()`: Регистрирует все доступные компоненты
- Компоненты регистрируются в словарях (MODEL_REGISTRY, ENV_REGISTRY и т.д.)

**Функции фабрики** (`hpo_rl/core/factory.py`):
- `build_backend(config)`: Создает экземпляры backend
- `build_env(config, backend, hp_space)`: Создает экземпляры среды
- `build_trainer(config)`: Создает экземпляры тренера
- `build_optimizer(model, hparams)`: Создает экземпляры оптимизатора

**Паттерн Builder** (`hpo_rl/core/builder.py`):
- `OptimizerBuilder`: Абстрактный интерфейс для построения оптимизатора
- `AdamBuilder`, `SGDBuilder`: Конкретные строители для конкретных оптимизаторов
- Поддерживает извлечение гиперпараметров и значения по умолчанию

#### 4. Models и Trainers

**Models** (`hpo_rl/models/`):
- `BaseModel`: Абстрактный базовый класс для ML-моделей
- `SimpleCNN`: Пример CNN-модели
- В настоящее время минимальное использование - фокус на гиперпараметрах оптимизатора, а не на архитектуре модели

**Trainers** (`hpo_rl/trainers/`):
- `BaseTrainer`: Абстрактный базовый класс
- `TorchTrainer`: Реализация тренера на основе PyTorch
- Обрабатывает обучение модели и возвращает историю

## Система конфигурации

### Формат конфигурации YAML

Эксперименты настраиваются через YAML-файлы в директории `configs/`:

```yaml
experiment_name: "experiment_name"

backend:
  name: "OptimizationBenchmarkBackend"
  params:
    function_name: "rastrigin"  # или sphere, rosenbrock и т.д.
    dimensions: 5
    maximize: false
    noise_std: 0.0

environment:
  name: "CyclicPipelineEnv"
  params:
    num_bins: 100
    max_steps: 100
    sparse_reward: false
  hp_space:
    x0:
      continuous:
        type: float
        log: False
        range: [-10.0, 10.0]
    # ... больше гиперпараметров

agent:
  name: "PPO"  # или A2C, DQN, SAC, TRPO, MaskablePPO, RecurrentPPO
  policy: "MultiInputPolicy"
  params:
    learning_rate: 0.003
    gamma: 0.95
    verbose: 1

training:
  total_timesteps: 25000
```

### Определение пространства гиперпараметров

Гиперпараметры могут быть определены как:

**Непрерывные:**
```yaml
param_name:
  continuous:
    type: float  # или int
    log: False   # логарифмическая шкала или линейная
    range: [low, high]
```

**Дискретные:**
```yaml
param_name:
  discrete:
    choices: [val1, val2, val3, ...]
```

## Использование

### Запуск экспериментов

**Точка входа:**
```bash
python run_experiment_new.py --config configs/function_test.yaml
```

**Поток эксперимента:**
1. Загружает YAML-конфигурацию
2. Создает backend (например, OptimizationBenchmarkBackend)
3. Генерирует или загружает пространство гиперпараметров
4. Создает среду с backend и hp_space
5. Создает RL-агента (PPO, A2C и т.д.) со средой
6. Обучает агента на указанное количество шагов
7. Оценивает производительность агента
8. Опционально выполняет перенос обучения на новую задачу

**Пример переноса обучения:**
Скрипт `run_experiment_new.py` включает рабочий процесс переноса обучения:
- Обучение на Задаче A (например, функция Rastrigin)
- Оценка zero-shot на Задаче B (например, функция Sphere)
- Few-shot дообучение на Задаче B
- Финальная оценка

### Пример: Оптимизация функции

```python
from hpo_rl.core.factory import build_backend, build_env
from hpo_rl.core.register import initialize_framework
from stable_baselines3 import PPO

initialize_framework()

# Создание backend
backend_cfg = {
    "name": "OptimizationBenchmarkBackend",
    "params": {
        "function_name": "rastrigin",
        "dimensions": 6,
        "maximize": False
    }
}
backend = build_backend(backend_cfg)

# Определение пространства гиперпараметров
hp_space = {
    "x0": {"continuous": {"type": float, "log": False, "range": [-5.12, 5.12]}},
    # ... больше параметров
}

# Создание среды
env_cfg = {
    "name": "CyclicPipelineEnv",
    "params": {"num_bins": 100, "max_steps": 200}
}
env = build_env(env_cfg, backend=backend, hp_space=hp_space)

# Создание и обучение агента
agent = PPO("MultiInputPolicy", env, verbose=1)
agent.learn(total_timesteps=10000)
```

## Поддерживаемые RL-алгоритмы

Проект поддерживает несколько алгоритмов из Stable-Baselines3:

- **PPO** (Proximal Policy Optimization)
- **A2C** (Advantage Actor-Critic)
- **DQN** (Deep Q-Network)
- **SAC** (Soft Actor-Critic)
- **TRPO** (Trust Region Policy Optimization)
- **MaskablePPO** (для маскирования дискретных действий)
- **RecurrentPPO** (для последовательных зависимостей)

## Эталонные функции

`OptimizationBenchmarkBackend` поддерживает следующие эталонные функции:

1. **Sphere**: Простая выпуклая функция, легко оптимизируется
2. **Rosenbrock**: Долинообразная, средняя сложность
3. **Rastrigin**: Много локальных минимумов, сложная
4. **Ackley**: Много локальных минимумов с крутыми склонами
5. **Griewank**: Многоэкстремальная функция
6. **Schwefel**: Очень обманчивая, много локальных минимумов
7. **Levy**: Сложная многомодальная функция
8. **Michalewicz**: Крутые гребни, оптимум зависит от размерности

## Философия проектирования

### Текущий подход

Проект в настоящее время оптимизирует **процесс выбора гиперпараметров**, а не напрямую оптимизирует гиперпараметры. Это означает:
- RL-агент изучает стратегию/последовательность действий
- Действия соответствуют выбору или корректировке гиперпараметров
- Награда основана на производительности финальной конфигурации

### Планируемая эволюция

Согласно README, проект направлен на смещение фокуса на:
- Оптимизацию **гиперпараметров оптимизатора** (learning rate, планировщики и т.д.)
- Включение **переноса знаний** между задачами
- Поддержку сценариев **few-shot обучения**
- Потенциальное расширение до стратегий аугментации данных

## Логирование и мониторинг

Прогресс обучения логируется с использованием обертки Monitor из Stable-Baselines3:
- Логи сохраняются в `logs/{agent_name}/task_*.monitor.csv`
- Включает метрики, такие как длина эпизода, награда и пользовательская информация (например, `best_metric`)
- Визуализация доступна через `plot.py`

## Ключевые концепции

### Формирование награды (Reward Shaping)

Разные среды используют разные стратегии награды:
- **Разреженные награды**: Награда только при завершении эпизода
- **Плотные награды**: Промежуточные награды за улучшения
- **Сформированные награды**: Логарифмическое масштабирование, бонус за лучшее-на-данный-момент

### Инженерия наблюдений

Наблюдения обычно включают:
- Текущий шаг/позиция в выборе гиперпараметров
- Нормализованные значения выбранных гиперпараметров
- Индикатор активного параметра (для циклических сред)
- Предыдущая дельта награды (для циклических сред)

### Проектирование пространства действий

Действия преобразуются в значения гиперпараметров через:
1. Нормализацию в диапазон [0, 1]
2. Масштабирование до фактических диапазонов параметров
3. Логарифмическое преобразование (если указано)
4. Преобразование типа (int/float)

## Примечания

- Проект активно разрабатывается
- Некоторые компоненты имеют несогласованные интерфейсы (отмечено в комментариях кода)
- В настоящее время фокус на оптимизации функций для тестирования
- Обучение реальных ML-моделей поддерживается, но менее протестировано
